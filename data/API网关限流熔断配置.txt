API网关限流与熔断配置指南

一、限流（流量控制）

限流是流量控制中最常用的手段之一，能有效地防止外部请求超出后端服务的承载能力，从而避免发生级联雪崩。在高并发场景下，限流可以通过阻止一部分请求来保证后端服务一直可用。

流量控制原理：监控路由的QPS指标，当指标达到设定的阈值时立即拦截流量，避免后端服务被瞬时的流量高峰冲垮。

配置参数说明：
- 总体QPS阈值：设置允许的最大每秒请求数
- Web fallback行为：选择"返回指定内容"或"跳转到指定页面"
- HTTP状态码：默认429（Too Many Requests）
- 返回content-type：普通文本或JSON
- HTTP返回文本：返回给客户端的提示信息

阈值计算规则：配置的阈值为整体阈值，每个网关节点的限流阈值=整体阈值/节点数，若限流阈值为小数则向上取整。例如，总体QPS为1001，网关节点数量为2，则每个节点的QPS限制为501。

二、并发控制

并发控制原理：统计当前网关处理中的请求数之和，当指标达到设定的阈值时立即拦截流量，可配置为后端服务的最大并发处理请求数，实现在高并发下的后端服务可用性保护。

配置参数说明：
- 总体并发数阈值：设置允许的最大并发处理请求数
- Web fallback行为：选择"返回指定内容"或"跳转到指定页面"
- HTTP状态码：默认429

三、熔断

熔断原理：监控路由的响应时间或异常比例，当达到指定的阈值时立即降低依赖优先级。在指定的时间内，系统不会调用该不稳定的资源，避免后端服务受到影响，从而保障后端的高可用性。当指定时间过后，再重新恢复对该资源的调用。

配置参数说明：
- 统计窗口时长：统计的时间窗口长度，取值范围1秒至120分钟
- 最小请求数目：触发熔断的最小请求数目，若当前统计窗口内的请求数小于此值，即使达到熔断条件规则也不会触发
- 阈值类型：慢调用比例（%）或异常比例（%）
  慢调用比例：设置允许的慢调用RT（最大响应时间），请求的响应时间大于该值则统计为慢调用。在降级阈值中设置触发熔断的慢调用比例。
  异常比例：在降级阈值中设置触发熔断的异常比例。
- 慢调用RT：允许的最大响应时间
- 熔断比例阈值：触发熔断的比例，取值范围0-100
- 熔断时长（秒）：熔断触发后持续的时间，资源进入熔断状态后，在配置的熔断时长内请求都会快速失败

熔断恢复机制：经过熔断时长后，熔断器会进入探测恢复状态。若接下来的一个请求响应时间小于设置的慢调用RT，则结束熔断；若大于设置的慢调用RT，则会再次被熔断。

四、限流策略选择建议

1. API配额场景：使用limit-count（请求计数限流），适合实现API配额计划（如每天10000次请求）
2. 突发流量场景：使用令牌桶算法，允许一定程度的突发流量
3. 后端保护场景：使用并发控制，限制同时处理中的请求数
4. 服务降级场景：使用熔断，当后端响应变慢或异常时自动降级

五、验证方法

未开启限流策略的响应：
  HTTP/1.1 200 OK
  content-type: application/json

开启限流策略后的响应（HTTP状态码429）：
  HTTP/1.1 429 Too Many Requests
  x-local-rate-limit: true

六、最佳实践

1. 限流阈值应根据后端服务的实际承载能力设置，建议先进行压测确定阈值
2. 熔断的慢调用RT应略大于后端服务的正常响应时间
3. 熔断恢复后应逐步放量，避免恢复瞬间流量涌入
4. 限流和熔断应配合使用，限流防止外部流量过载，熔断防止后端异常扩散
5. 建议同时配置监控告警，当限流或熔断触发时及时通知
