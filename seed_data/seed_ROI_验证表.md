## 四、数据使用说明

1. **直接导入**：三张 CSV 字段与《MVP 开发文档》第六章数据模型对齐，可直接建表导入。
2. **错误码库是 P0 核心**：40 个错误码的 `solution` 字段已写成可直接当草稿种子的具体话术，一线版 `error_code` 表直接用。
3. **历史工单做向量召回**：`raw_text` 是客户口语原话，`solution_text` 是已脱敏的解法，灌入向量库做相似工单召回。
4. **客户上下文**：`seed_customers.csv` 的 version / enabled_modules / recent_changes 用于草稿自动带出"贵司当前版本 v4.2.1"这类个性化句子。
5. **埋点基线**：`handle_minutes` 字段是上线前的"平均处理时长"基线，上线后对比系统记录的 `latency_ms` + 主观省时反馈。
6. **冷启动不要改**：不要为了"数据更多"再编一批假工单；这 202 条已经够 MVP 回灌评测用。真实试点后再用真实工单替换。

## 五、模拟数据的局限（写进交付说明）

- 这是**虚构商家和产品**，不是贵司真实业务；开发时若换成真实业务，错误码库和客户表需要按贵司实际系统重做。
- `solution_text` 为模拟解法，演示时能用，正式上线前必须由二线工程师核对。
- 时间分布均匀化，真实工单有周末/大促峰值差异，试点数据会比这更不均匀——这是正常的。
