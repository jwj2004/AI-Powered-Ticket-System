# 「知答」企业内部知识库智能问答 Agent · 完整开发文档

> 三人团队，FastAPI + Vue + SQLite + FAISS + DeepSeek。服务客服、运维、新人、管理员三类角色。核心原则：宁可不答，不可错答；文档靠系统养，不靠人记。

---

## 一、项目定位

部署在企业内网的知识库问答系统：员工登录后自由提问，系统从内部文档检索证据、带引用回答，支持多轮对话和跨会话记忆；管理员在后台管理文档（上传、在线编辑、权限）、看数据看板、补全知识缺口；补全后自动通知原提问者。

## 三、知识缺口闭环流程（核心特色）

```
员工提问
  → 系统判断证据不足
  → 自动记入 knowledge_gap 表（含提问人、问题、时间）
  → 员工看到："这个问题我没把握，已记录，管理员补全后会通知你"
  → 管理员在后台"知识缺口"榜单看到这个问题
  → 管理员二选一：
      A. 补一篇文档（上传/在线编辑）→ 保存后自动重新向量化
      B. 直接在后台写一段答案 → 入库
  → 系统把新答案和提问人关联
  → 员工下次登录问答页，右上角看到红点通知：
      "你问的『订单导出超时怎么办』已有答案，点击查看"
  → 员工点进去看到新答案
```

这是让系统"越用越聪明"的关键，不是静态知识库。

## 四、LangGraph 多智能体编排

不搞复杂，一个线性流：

```
用户提问
  → [路由节点] 判断问题类型：
      ├─ 事实性/结构化问题（错误码、配置项）→ 直查结构化表
      ├─ 开放问题 → 走 RAG
      └─ 算不清/闲聊 → 直接拒答
  → [检索节点] 向量召回 top5 相关文档块
  → [生成节点] LLM 拼证据 → 生成带引用回答
  → [质量节点] 判断：
      ├─ 证据充分 → 返回回答
      └─ 证据不足 → 不硬答，写入 knowledge_gap，转人工
  → [反馈节点] 记录赞/踩，踩多了进入缺口榜单
```

用 LangGraph 实现这五个节点，节点之间用条件边跳转。不做子智能体嵌套。

## 五、技术架构

| 层 | 选型 |
|----|------|
| 后端 | Python 3.10 + FastAPI + LangGraph |

| doc_version | id, document_id, version, content, created_at |

## 八、接口概览

```
POST /api/auth/login              登录返回 JWT
GET  /api/documents                文档列表（按权限过滤）
POST /api/documents/upload         上传文档
PUT  /api/documents/{id}           在线编辑保存
DELETE /api/documents/{id}         删除文档
GET  /api/documents/{id}/versions  版本历史
POST /api/chat                     提问（带 conversation_id）
POST /api/feedback                 赞/踩
GET  /api/gaps                     知识缺口榜单（管理员）
POST /api/gaps/{id}/resolve        管理员补答案
GET  /api/notifications            我的通知
GET  /api/dashboard                看板数据
```
