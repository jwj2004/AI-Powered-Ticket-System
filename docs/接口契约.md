# 知答 MVP · 接口契约（D1 冻结）

> **这是三个人之间的法律。** 字段名、类型、空值约定，从 D1 起冻结。要改必须在群里说，且 PR 标题带 `[contract]`。
> 实现方式：C 的 `main.py` 里定义 Pydantic model，Swagger UI 在 `http://127.0.0.1:8000/docs` 自动生成，不另写文档。

---

## 〇、通用约定（先对齐这些，再看接口）

| 项 | 约定 |
|----|------|
| Base URL | `http://127.0.0.1:8000` |
| 字段命名 | **snake_case**（如 `customer_id`，不是 `customerId`） |
| 时间格式 | ISO 字符串 `"2026-09-15T10:30:00"`，不用时间戳 |
| 空值 | 用 JSON `null`，**不用空字符串**。没命中错误码就 `error_code: null`，不是 `""` |
| 错误返回 | 统一格式：`{"detail": "错误说明"}`，HTTP 状态码用 4xx/5xx，不要在 200 里塞 error 字段 |
| 置信度枚举 | 只有两个值：`"high"` / `"low"`，不要造 `"medium"` |
| 字符编码 | UTF-8 |
| 同步/异步 | 全部同步返回，不做 SSE。超时 10 秒，超时前端自己提示 |

## 一、错误码秒查

```
GET /api/lookup?code={code}
```

**Request**
- query 参数 `code`：字符串，错误码，如 `PAY_CALLBACK_TIMEOUT`

**Response 200**

```json
{
  "code": "PAY_CALLBACK_TIMEOUT",
  "name": "支付回调超时",
  "meaning": "买家已付款但商城订单长时间未变成已支付",
  "trigger_condition": "买家付款后 5 分钟内未收到支付平台异步通知",
  "causes": ["商户平台回调地址不通", "店铺刚升级过版本回调路径变更"],
  "solution": "先在支付商户后台手动查询该笔订单支付状态...",
  "related_versions": ["v4.1.0+"]
}
```

**未命中时**（code 不存在）

```json
{
  "code": "NOT_EXIST",
  "name": "",
  "meaning": "",
  "trigger_condition": "",
  "causes": [],
  "solution": "",
  "related_versions": []
}
```

> 注意：未命中返回 200，不是 404。前端拿到空字符串就不渲染错误码区块。

## 二、草稿生成（核心接口）

```
POST /api/draft
```

**Request**

```json
{
  "raw_text": "客户说已经微信付了198块钱，但是后台订单一直是待支付",
  "customer_id": "C003"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| raw_text | string | 是 | 客户原话，前端粘贴的内容 |
| customer_id | string / null | 否 | 从工单页面解析到的客户 ID；解析不到就传 null |

**Response 200（证据充分）**

```json
{
  "error_code": "PAY_CALLBACK_TIMEOUT",
  "evidence": [
    { "ticket_id": "T20260715001", "summary": "同现象：微信付款后订单待支付..." },
    { "ticket_id": "T20260721001", "summary": "..." }
  ],
  "draft": "您好，已为您核实该笔订单。您当前店铺版本 v3.8.5...",
  "confidence": "high"
}
```

**Response 200（证据不足，"宁可不答"）**

```json
{
  "error_code": null,
  "evidence": [],
  "draft": null,
  "confidence": "low",
  "message": "未找到可靠依据，建议转二线处理"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| error_code | string / null | 命中错误码时返回 code，否则 null |
| evidence | array | 相似工单摘要，最多 3 条；没找到就是空数组 |
| evidence[].ticket_id | string | 来源工单号，前端可展示但不可点 |
| evidence[].summary | string | 一句话摘要，不要把整段 solution 塞进来 |
| draft | string / null | 对外答复草稿。confidence=low 时必须为 null |
| confidence | string | `"high"` 或 `"low"` |
| message | string / null | 只有 confidence=low 时才有，告诉用户该怎么办 |

## 三、反馈埋点

```
POST /api/feedback
```

**Request**

```json
{
  "query_id": "q_20260915_001",
  "copied": true,
  "thumbs_down": false
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| query_id | string | 每次调 `/api/draft` 时后端生成并返回的唯一 ID（见下方） |
| copied | bool | 用户是否点了"复制草稿" |
| thumbs_down | bool | 用户是否点了"踩" |

**Response 200**

```json
{ "ok": true }
```

> **契约补充**：`/api/draft` 的 response 里必须带一个 `query_id` 字段（字符串），用于 C 复制时上报。这个字段上面示例漏了，现在补上：
>
> ```json
> {
>   "query_id": "q_20260915_abc123",
>   "error_code": "PAY_CALLBACK_TIMEOUT",
>   "evidence": [...],
>   "draft": "...",
>   "confidence": "high"
> }
> ```

## 四、内部接口（B 调 A，不对外）

```
POST /api/retrieve
```

**Request**

```json
{
  "query": "客户说付了钱订单没更新",
  "customer_id": "C003",
  "top_k": 3
}
```

**Response 200**

```json
{
  "error_code": "PAY_CALLBACK_TIMEOUT",
  "tickets": [
    { "ticket_id": "T20260715001", "solution_text": "...", "score": 0.87 }
  ]
}
```

> 这个接口只有 B 调，不经过 C 的前端。`error_code` 是 A 从客户原话里识别出来的，识别不到就是 null。

## 六、契约变更规则

- **禁止静默改字段**。加字段、改字段名、改类型，必须群里说。
- **加可选字段**：可以，不破坏现有调用。比如以后加个 `customer_version`。
- **改现有字段**：不可以。要么加新字段，要么这版就这么定。
- **真要改**：PR 标题写 `[contract] xxx`，A/B/C 三个人 review，至少两个人同意才合。
