# 「知答」MVP · 三人开发分工文档

> 配套《知答-MVP-工单智能副驾-开发文档》使用。本文档解决一件事：三个人怎么在 5 天里并行把 P0 两颗钉子做完，谁也不等谁。
> **前端方案已从油猴浮层改为 Vue 3 + Vite 独立页面**，A/B 的后端任务不变。

---

## 一、角色与职责

| 角色 | 负责模块 | 一句话目标 | 关键交付物 |
|------|---------|-----------|-----------|
| **A · 数据检索后端** | 建表灌数据、错误码秒查、向量召回、客户上下文、埋点表 | 让系统"查得到、查得准" | `/api/lookup`、`/api/retrieve`、`/api/tickets/{id}/context`、`query_log` |
| **B · 草稿生成后端** | LLM prompt、草稿生成、"无引用不输出"硬规则、引用拼接 | 让草稿"敢直接发给客户" | `/api/draft`、prompt 模板、硬规则逻辑 |
| **C · 前端与工程** | FastAPI 骨架、Vue 前端页面、接口契约、埋点上报、部署 | 让一线打开网页就能用 | Vue 页面、mock 接口、docker-compose、部署说明 |

> 不按"前端/后端"硬切（后端工作量远大于前端），也不按"P0-1/P0-2"切（前端只有一份，两人同时写必打架）。

---

## 二、五天排期 × 三人

| 天 | A · 数据检索 | B · 草稿生成 | C · 前端与工程 |
|----|-------------|-------------|---------------|
| **D1 骨架+契约** | 建 5 张表、灌三张 CSV、SQLite 初始化 | 写 2 套 prompt（错误码命中版 / 纯相似工单版），先跑 10 个例子看效果 | FastAPI 骨架 + 三个 mock 接口 + CORS；用 Vite 起 Vue 项目，写好 `App.vue` 静态页面 |
| **D2 各自跑通** | `/api/lookup` 错误码精确查（P95<0.5s）+ `/api/tickets/{cid}/context`；内部 `/api/retrieve` 先返回写死的 3 条假证据 | 调 `/api/retrieve` 的 mock，用假证据把"证据→草稿"链路跑通，不接真实检索 | `App.vue` 里用假数据把页面布局跑通（输入框、三块结果、复制按钮），不接真接口 |
| **D3 接真数据** | `/api/retrieve` 接真实检索，返回 top3 相似工单 + 来源工单号；错误码命中时优先用结构化 solution | `/api/draft` 完整接 A 的检索结果 + 客户版本号 + 引用拼接 | `App.vue` 的 fetch 从假数据换成真 `/api/draft`，端到端走通"输入→生成→复制" |
| **D4 质量+埋点** | `query_log` 表 + `/api/feedback` 接口（copied / thumbs_down） | **"无引用不输出"硬规则**：检索为空或低置信 → 不返回 draft，只回"未找到可靠依据，建议转二线" | 复制按钮调 `/api/feedback`；加 loading 和错误提示；写部署说明 |
| **D5 评测+试点** | 写 30 条历史工单回灌脚本，统计"草稿改两句就能发"的比例 | 根据 A 的评测结果调 prompt、调硬规则阈值 | 拉 2-3 个同学试用页面，导出 query_log 看人均使用次数 |

## 三、接口契约

详见同目录 `接口契约.md`。D1 三个人花半小时过一遍，之后字段冻结。三个核心接口：

```
GET  /api/lookup?code=XXX
POST /api/draft      body: {raw_text, customer_id}
POST /api/feedback   body: {query_id, copied, thumbs_down}
```

前端跑在 `http://127.0.0.1:5173`，后端跑在 `http://127.0.0.1:8000`，FastAPI 已配 CORS 允许跨域。

## 四、并行策略（怎么不互相等）

| 依赖点 | 解耦方式 |
|--------|---------|
| B 要等 A 的检索结果 | D2 A 的 `/api/retrieve` 先返回写死的 3 条假证据，B 用假数据写 prompt 和生成逻辑，D3 再接真的 |
| C 要等后端接口 | D1 C 的 `App.vue` 先用本地假数据渲染，D2 接 mock 接口，D3 接真接口 |
| A 要等数据 | 三张 CSV 已经准备好，D1 直接灌，不等人 |
| 联调冲突 | D3 才第一次合代码，D1/D2 每天各自 merge 一次 main，不要攒到最后 |

---

## 五、协作规则

1. **Git 从 D1 就用**：main 分支保护，每人开 feature 分支：
   - A → `feat/lookup-retrieve`
   - B → `feat/draft-generate`
   - C → `feat/frontend-api`
   每天下班前 merge 一次 main，**不要攒到 D3 才合并**。
2. **每天 15 分钟站会**：说三件事——昨天做了什么、今天做什么、有没有卡别人。卡人就当场拉相关的人对。
3. **统一环境**：D1 第一天对齐 Python 3.10、Node 18+、依赖清单，写完一个人上传，其他人直接 `npm install` / `pip install -r`。
4. **接口改了就在群里喊**：契约冻结后如果真要改，A/B/C 必须第一时间知道，不要静默改字段名。

## 六、验收时各自对什么负责

| 指标 | 负责人 |
|------|--------|
| 错误码查询 P95 < 0.5 秒 | A |
| 粘贴问题 ≤ 3 秒返回草稿 | B（生成耗时）+ C（网络/前端渲染） |
| 问一个知识库里没有的问题，系统必须说"没把握"而不是硬编 | B |
| 网页能打开、输入框能用、草稿能复制 | C |
| 30 条历史工单回灌里，草稿"改两句就能发"的比例 ≥ 50% | A 出数、B 改善 |
| query_log 能导出人均使用次数、复制率、点踩率 | A（表+接口）、C（上报） |

## 七、风险与兜底

| 风险 | 兜底方案 |
|------|---------|
| B 的 LLM 草稿质量不行，D3 接完不能看 | A 的错误码表 `solution` 字段本身就是高质量话术，**命中错误码时直接返回 solution 当草稿，不调 LLM**——这是质量兜底，也是最快的路径 |
| A 的检索不准，相似工单召回的是不相关的 | 错误码精确匹配优先（客户原话里带错误码就直接命中），相似工单只是补充证据，不是主路径 |
| Vite 前端调 FastAPI 跨域失败 | main.py 已配 `CORSMiddleware allow_origins=["*"]`，开发期不用管；真报错检查后端起没起 |
| D3 联调发现接口字段对不上 | D1 契约写细一点，连空值和字段名都定死；真对不上就当天改，不要拖 |
| 三个人水平不均，某人卡住 | A 的活最轻，随时支援 B 写 prompt 或 C 写前端 |

## 九、技术栈一览

| 层 | 选型 |
|----|------|
| 后端 | Python 3.10 + FastAPI + Uvicorn + Pydantic v2 |
| 数据库 | SQLite |
| 前端 | Vue 3 + Vite（JS，无 Router/Pinia/UI 库） |
| HTTP | 同步 JSON，无 SSE |
| 部署 | docker-compose（仅后端；前端 `npm run build` 后由 nginx 托管或直接开 dev server） |
